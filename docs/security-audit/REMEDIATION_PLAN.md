# 安全修復計畫

日期：2026-10-26。依據：同目錄的 2026-10-26.md。

## 執行順序與驗收條件

1. **依賴安全**：升級 TLS 信任鏈、Tokio 等有公告的套件；移除可替代的停止維護 API。檢查 rumqttc 上游版本與相容性，對無法直接升級的間接依賴確認實際可達性。驗收：最新 RustSec 稽核無未說明的漏洞，所有例外必須有範圍與到期日；盡量維持 Rust 1.86，若上游已要求更新則如實調整並驗證。
2. **秘密遮蔽**：為 Builder 與 TLS options 手寫 Debug，避免帳密、私鑰、原始 broker URL 或自訂 TLS config 洩漏。驗收：對直接及巢狀 Debug 輸出加入回歸測試。
3. **設定安全**：拒絕明文 scheme 搭配 TLS 設定；未編譯 TLS 時明確拒絕 TLS options；依協定版本驗證 keep-alive 下限與封包欄位上限。驗收：先前安全探針改為驗證安全行為，涵蓋預設與 feature 邊界。
4. **持續防護**：固定 CI／Release Action 的 commit SHA，加入依賴稽核、鎖定檔檢查、敏感檔案忽略規則。驗收：工作流程結構及命令經檢查，可在未建立遠端倉庫的情況下完成本地驗證。
5. **開源文件**：製作繁體中文 README，提供清楚的定位、功能、安裝狀態、可執行範例、安全設定、feature 表、限制與貢獻入口；補上必要的安全政策與現有雙授權聲明對應的授權檔。避免虛構 crates.io 發布、GitHub 連結或 CI 徽章。
6. **最終驗證**：fmt、Clippy、所有測試、features、文件、examples、MSRV 與 RustSec。將結果、剩餘限制及版本變動記錄於完成報告。保留原始審計為歷史快照，不建立遠端倉庫、不推送。
